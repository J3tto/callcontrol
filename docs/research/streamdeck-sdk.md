# Stream Deck SDK for a long-running, state-watching plugin

Research for issue #5. Checked 2026-10-14 against docs.elgato.com, the `elgatosf/streamdeck` monorepo (`main`), and the published npm packages `@elgato/streamdeck@3.0.2`, `@elgato/cli@1.10.2`, `@elgato/schemas@0.5.2`. Sources are inline; anything not backed by a primary source is marked **unverified**.

**Naming note:** the ticket says "SDK v2". The current major is **3.x** (`@elgato/streamdeck@3.0.2`); v3 requires Stream Deck 7.1+ and Node 24+, which matches our targets, so this doc covers v3 ([v3 upgrade guide](https://docs.elgato.com/streamdeck/sdk/releases/upgrading/v3), [README](https://github.com/elgatosf/streamdeck/blob/main/README.md)).

## 1. Process lifecycle

- **Launch.** Stream Deck starts the plugin as a console process with `-port`, `-pluginUUID`, `-registerEvent`, `-info` arguments; the plugin must open a WebSocket to that port and send a registration message ([WebSocket ref](https://docs.elgato.com/streamdeck/sdk/references/websocket/plugin)). The SDK does this in `streamDeck.connect()`: it parses `process.argv`, opens `ws://127.0.0.1:<port>`, and resolves once registered ([connection.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/connection.ts)). Register all actions before `connect()`; call it last in the entry file ([Actions guide](https://docs.elgato.com/streamdeck/sdk/guides/actions)).
- **Working directory = the `.sdPlugin` folder.** The SDK reads `manifest.json`, locale files and the log directory from `process.cwd()`, and derives the plugin UUID from `basename(process.cwd())` ([manifest.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/manifest.ts), [utils.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/common/utils.ts), [logging/index.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/logging/index.ts)). So `path.join(process.cwd(), "bin/helper")` is the canonical way to locate a bundled binary.
- **Node flags.** All Node plugins run with `--enable-source-maps` and `--no-global-search-paths` ([Manifest ref](https://docs.elgato.com/streamdeck/sdk/references/manifest)).
- **Stop/restart/crash.** Docs say only that "Stream Deck is responsible for managing your plugin's lifecycle, and provides automatic failure recovery in the event an unexpected error occurs"; the detail is an SVG diagram with no extractable text ([Plugin Environment](https://docs.elgato.com/streamdeck/sdk/introduction/plugin-environment)). `streamdeck stop <uuid>` and `streamdeck restart <uuid>` exist and are implemented as `open streamdeck://plugins/{stop|restart}/<uuid> -g` ([restart.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/cli/src/commands/restart.ts), [runner.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/cli/src/common/runner.ts)). The SDK registers **no** `close`/`error` handler on the socket and has no reconnect or `process.exit` path ([connection.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/connection.ts)). **Unverified:** whether Stream Deck SIGTERMs or SIGKILLs plugins on app quit, and whether the plugin is started at app launch regardless of visible actions. The SDK keeps no "all actions gone, exit" logic, and `onWillAppear` "also occurs during startup if the action is on the front page" ([Actions guide](https://docs.elgato.com/streamdeck/sdk/guides/actions)), which only makes sense if the process is already running; treat "runs while no action is visible" as likely but unconfirmed.
- **Visibility.** `onWillAppear`/`onWillDisappear` fire on page/profile/folder navigation and startup ([Actions guide](https://docs.elgato.com/streamdeck/sdk/guides/actions)). The SDK adds the action to `streamDeck.actions` on `willAppear` and removes it on `willDisappear`; nothing else evicts it, including device disconnect ([service.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/actions/service.ts)). "The `context` of an action is not guaranteed to persist across app cycles" ([WebSocket ref](https://docs.elgato.com/streamdeck/sdk/references/websocket/plugin)).
- **Sleep/wake.** On wake the plugin receives `onWillAppear` for every visible action plus one `onSystemDidWakeUp`, documented as the hook to "restore connections / state" ([System guide](https://docs.elgato.com/streamdeck/sdk/guides/system)). No sleep event exists.
- **Devices.** `streamDeck.devices.onDeviceDidConnect/onDeviceDidDisconnect`; keys "can still be visible in the Stream Deck app while the hardware is disconnected" ([Devices guide](https://docs.elgato.com/streamdeck/sdk/guides/devices)). `-info` may list devices "not currently connected" ([WebSocket ref](https://docs.elgato.com/streamdeck/sdk/references/websocket/plugin)).

## 2. Node runtime and spawning a bundled binary

- Stream Deck 7.1–7.3 bundle Node **20.20.0 and 24.13.1**; "From Stream Deck 7.1, Node.js versions are automatically updated to the latest versions supported by Stream Deck" ([Plugin Environment](https://docs.elgato.com/streamdeck/sdk/introduction/plugin-environment)). 7.1.0 "Added support for Node.js 24, configurable within the manifest" ([Changelog](https://docs.elgato.com/streamdeck/sdk/references/changelog)). `Nodejs.Version` is `"20" | "24"` ([schema latest.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/schemas/src/streamdeck/plugins/manifest/latest.ts)).
- `child_process` is plain Node and needs no SDK support. Real plugins doing it: **jerez/sd-suite** spawns a SwiftPM-built `native/macos/audio-bridge` inside its `.sdPlugin` with `stdio: ["ignore","pipe","pipe"]`, locates it via `process.cwd()`, and kills it with SIGTERM ([mac.ts](https://github.com/jerez/sd-suite/blob/main/apps/audio-source/src/audio/mac.ts), [native-command.ts](https://github.com/jerez/sd-suite/blob/main/apps/audio-source/src/audio/native-command.ts)); **sigma/sd-herdr** notes "A Stream Deck plugin's PATH is launchd's `/usr/bin:/bin:/usr/sbin:/sbin` — measured, not assumed — so a bare name is `ENOENT`" and spawns everything by absolute path ([spawn.ts](https://github.com/sigma/sd-herdr/blob/main/src/raise/spawn.ts)).
- **Constraint — executable bit.** `streamdeck pack` writes the zip with `@zip.js/zip.js` `ZipWriter.add(name, stream)` and passes no `executable`/`externalFileAttributes` option, so Unix modes are not recorded ([pack.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/cli/src/commands/pack.ts); zip.js [index.d.ts](https://github.com/gildas-lormeau/zip.js/blob/master/index.d.ts) documents those options; the published `dist/index.js` of `@elgato/cli@1.10.2` contains neither string). **Unverified** what the installer does on extract. Mitigation: `fs.chmodSync(helper, 0o755)` before spawn, or run the helper through `/usr/bin/env`/a shell. Note Marketplace DRM wants shipped files immutable ([Distribution](https://docs.elgato.com/streamdeck/sdk/introduction/distribution)); irrelevant for a personal, linked install.
- **Helper hygiene.** Because the SDK never observes socket close, the plugin must itself handle `process.on("exit"|"SIGTERM"|"SIGINT")` and the socket's close (not exposed by the SDK) to kill the helper, else an orphan survives a Stream Deck quit (source-derived, see §1).

## 3. Action model

- Actions are `SingletonAction` subclasses registered with `streamDeck.actions.registerAction()`; `streamDeck.actions.forEach(a => { if (a.isKey()) ... })` updates every visible instance from anywhere, e.g. from the helper's stdout stream ([Actions guide](https://docs.elgato.com/streamdeck/sdk/guides/actions)). In v3 `Action` is a union `KeyAction | DialAction | NeoInfobarAction`; narrow with `isKey()`/`isDial()` ([v3 guide](https://docs.elgato.com/streamdeck/sdk/releases/upgrading/v3)).
- `KeyAction`: `setImage(image?, {state?, target?})`, `setState(n)`, `setTitle(title?, {state?, target?})`, `showAlert()`, `showOk()` ([key.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/actions/key.ts)). `DialAction` has `setFeedback`, `setFeedbackLayout`, `setImage`, `setTitle`, `setTriggerDescription`, `showAlert` ([dial.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/actions/dial.ts)). Dials need `Controllers: ["Encoder"]` and an `Encoder.layout` ([Dials guide](https://docs.elgato.com/streamdeck/sdk/guides/dials)). `Controllers` values: `"Keypad" | "Encoder" | "Neo"` ([schema](https://github.com/elgatosf/streamdeck/blob/main/packages/schemas/src/streamdeck/plugins/manifest/latest.ts)).
- `setImage` accepts a path inside the plugin folder, a base64 data URL, or an SVG string; SVG is recommended, PNG/JPG/WEBP work, GIF is not supported; `undefined` resets to the manifest image; the plugin cannot override a user-chosen custom image or title ([Keys guide](https://docs.elgato.com/streamdeck/sdk/guides/keys)). State images in the manifest are 72×72 / 144×144 ([Manifest ref](https://docs.elgato.com/streamdeck/sdk/references/manifest)).
- **Multi-state.** `States[]` of two makes a toggle; Stream Deck toggles automatically on press unless `DisableAutomaticStates: true`; `setState` is 0 or 1; more than two states is "not fully supported" ([Keys guide](https://docs.elgato.com/streamdeck/sdk/guides/keys), [Manifest ref](https://docs.elgato.com/streamdeck/sdk/references/manifest)). For six Teams states (muted, camera, hand, no call, not running, no permission) use one state and push a per-state SVG via `setImage`, or several actions. `UserTitleEnabled: false` lets the plugin own the title ([Manifest ref](https://docs.elgato.com/streamdeck/sdk/references/manifest)).
- **Rate.** Guidelines: "limit programmatic calls to a maximum of 10 per second" for keys and touch strips ([Plugin Guidelines](https://docs.elgato.com/guidelines/stream-deck/plugins)). The SDK has no throttling; nothing about flicker is documented. Push on change only.

## 4. Settings and property inspector

- Per-action settings: `ev.payload.settings`, `action.getSettings()/setSettings()`, plain-text, exported with profiles. Global settings: `streamDeck.settings.get/setGlobalSettings()`, plugin-scoped ([Settings guide](https://docs.elgato.com/streamdeck/sdk/guides/settings)). In v3 `onDidReceiveSettings` fires only on PI changes ([v3 guide](https://docs.elgato.com/streamdeck/sdk/releases/upgrading/v3)).
- **No PI is fine.** `PropertyInspectorPath` is optional at action and plugin level; "When `undefined`, the manifest's top-level `PropertyInspectorPath` is used, otherwise none" ([schema latest.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/schemas/src/streamdeck/plugins/manifest/latest.ts), [Manifest ref](https://docs.elgato.com/streamdeck/sdk/references/manifest)). Guidelines only ask for a PI where actions have settings ([Plugin Guidelines](https://docs.elgato.com/guidelines/stream-deck/plugins)).

## 5. Manifest essentials (macOS only)

Required: `UUID`, `Name`, `Author`, `Description`, `Version` (`x.y.z.build`), `Icon` (PNG 256/512, extension-less), `CodePath` (with extension, e.g. `bin/plugin.js`), `OS` (`{Platform:"mac", MinimumVersion:"12"}`; one entry is allowed), `Software.MinimumVersion` (enum; `"7.1"` for v3), `SDKVersion: 3`, `Actions[]` with `UUID`, `Name`, `Icon` (20/40 px), `States[]` ([Manifest ref](https://docs.elgato.com/streamdeck/sdk/references/manifest), [schema JSON](https://www.npmjs.com/package/@elgato/schemas)). `Nodejs: { Version: "24", Debug: "enabled" }`; `Debug` is stripped by `pack` ([pack.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/cli/src/commands/pack.ts)). This is exactly what `streamdeck create` emits ([template manifest](https://www.npmjs.com/package/@elgato/cli), `template/com.elgato.template.sdPlugin/manifest.json.ejs`).

## 6. Packaging and dev loop

- `npm i -g @elgato/cli@latest`; `streamdeck`/`sd` ([CLI intro](https://docs.elgato.com/streamdeck/cli/intro)). Engines: cli `node>=20.1.0`, sdk `node>=20.5.1` (package.json of each).
- `streamdeck validate [path] --no-update-check` ("recommended when using the CLI as part of a build pipeline"; otherwise it fetches schema updates from `https://schemas.elgato.com` daily) ([validate](https://docs.elgato.com/streamdeck/cli/commands/validate), [store.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/cli/src/json/store.ts)). Rules: manifest schema, referenced files exist, UUIDs, category, URLs, layouts ([rules/](https://github.com/elgatosf/streamdeck/tree/main/packages/cli/src/validation/plugin/rules)).
- `streamdeck pack <dir> [--output d] [--force] [--version v] [--dry-run]` validates, zips, writes `<uuid>.streamDeckPlugin`; default ignores `.sdignore .git /.env* *.log *.js.map` ([pack](https://docs.elgato.com/streamdeck/cli/commands/pack), [fs.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/cli/src/system/fs.ts)). Neither `validate` nor `pack` touches the Stream Deck app or plugin folder (sources above), so both run on a GitHub Actions macOS runner with just Node; `.sdignore` must not exclude the helper binary.
- `streamdeck link [path]` symlinks the dir into `~/Library/Application Support/com.elgato.StreamDeck/Plugins/` ([link.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/cli/src/commands/link.ts), [stream-deck.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/cli/src/stream-deck.ts)); `streamdeck dev` runs `defaults write com.elgato.StreamDeck developer_mode -bool YES` ([dev.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/cli/src/commands/dev.ts)); `restart`/`stop` use the `streamdeck://` URL and start the app if not running ([restart.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/cli/src/commands/restart.ts)). Template `watch` script: `rollup -c -w --watch.onEnd="streamdeck restart <uuid>"`; rollup bundles `src/plugin.ts` to `bin/plugin.js` and emits `{ "type": "module" }` ([template](https://www.npmjs.com/package/@elgato/cli)).
- Code signing/notarization of bundled binaries: not mentioned anywhere in the SDK docs ([Distribution](https://docs.elgato.com/streamdeck/sdk/introduction/distribution)). **Unverified** whether Gatekeeper blocks an unsigned helper spawned by the Stream Deck-launched Node; a locally built, locally linked binary carries no quarantine attribute.

## 7. Logging

- `streamDeck.logger` writes `<cwd>/logs/<uuid>.<n>.log`; `0` is current; rotation at start or size limit; 10 files kept ([Logging guide](https://docs.elgato.com/streamdeck/sdk/guides/logging), [logging/index.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/logging/index.ts)). Docs say 10 MiB per file; `main` source sets `maxSize: 50 * 1024 * 1024` — discrepancy, trust whichever version ships.
- Level `info` in production, `debug` when `--inspect*` is in `execArgv` (i.e. `Nodejs.Debug` set); console target only in debug mode; `uncaughtException` is logged ([logging/index.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/logging/index.ts), [utils.ts](https://github.com/elgatosf/streamdeck/blob/main/packages/plugin/src/plugin/common/utils.ts)). Plain `console.log`/stderr capture is undocumented; pipe helper stderr into the logger.
- App logs: `~/Library/Logs/ElgatoStreamDeck/StreamDeck0.log` ([Logging guide](https://docs.elgato.com/streamdeck/sdk/guides/logging)).

## 8. Constraints summary for the helper protocol and build

1. Spawn by absolute path under `process.cwd()`; PATH is launchd's minimal set.
2. Keep the helper alive independent of action visibility; re-sync state on `onWillAppear` and `onSystemDidWakeUp`; push updates to `streamDeck.actions` only on change, at most 10/s.
3. Own helper teardown on `exit`/signals; the SDK gives no socket-close hook.
4. Expect the exec bit to be lost by `pack`; chmod at startup or avoid `pack` for the personal install (link the built folder).
5. CI: `validate --no-update-check` and `pack` are app-independent; `link`/`restart`/`dev` are for the Mac dev loop only.
6. No PI needed; single-state actions with `setImage` SVGs cover the six Teams states.
